## 変えてはいけないもの

1. 意味、事実、数値、日付、固有名詞、URL を変えない
2. インラインコード、コードブロック、コマンド、ファイルのパス、エラーメッセージは 1 文字も変えない。コードブロックの中は校正の対象外として扱う
3. Markdown の構造（見出しのレベル、箇条書き、番号付きリスト、表、リンク、引用、改行の位置）を保つ。見出しや箇条書きを新しく足したり、段落を箇条書きに変えたりしない
4. 原文に無い情報、前置き、まとめ、注意書きを足さない
5. です・ます調か、だ・である調かは原文に合わせる
6. 実績や効果を原文より強く書かない（「一部で使う」を「任せる」「自動化した」に膨らませるなど）

## 直す規則

1. 技術用語は原語のまま書くか、日本の IT の現場で普通に使うカタカナで書く。現場で使わない和訳は、次の表の右の語に直す。表に無い語も同じ考えで直す

   | 使わない語 | 使う語 |
   |---|---|
   | 版 | バージョン |
   | 指紋 | fingerprint |
   | 上流、下流 | upstream、downstream |
   | 目印 | 特徴、シグネチャ |
   | 型、形（pattern の意味） | パターン |
   | 写し、写す | コピー、コピーする |
   | 道具 | ツール |
   | 窓（期間の意味） | ウィンドウ |
   | 控え | バックアップ |
   | 見張り | 監視 |
   | 手札 | 対策の候補 |
   | 受け口、口、入口（API の意味） | エンドポイント |
   | 管理役 | マネージャー |
   | 持ち主（人を指すとき） | オーナー |
   | 封筒 | エンベロープ |
   | 隠し場所 | キャッシュ |
   | 配備 | デプロイ |
   | 下見 | 偵察 |
   | 手当て | 緩和策 |
   | 引き金 | トリガー |
   | 合図 | シグナル |
   | 骨組み | スケルトン |
   | 秘密（secret の意味） | 認証情報、トークン、キーなど実体の言葉 |
   | 記録（log の意味） | ログ |

   反対に、日本の会社で普段使わないカタカナ（エグゼクティブサマリ、ステークホルダー、アジェンダ化など）は、普通の日本語（要約、関係者など）に直す
2. 体言止めと、言い切りの短い断片の文を使わない。地の文は動詞で結んだ完結した文にする。見出しと表のセルは名詞で終わってよい
3. 否定してから言い直す構文を使わない。対象は「X ではなく Y」「X ではない。Y だ」「X というより Y」「単なる X ではない」「X だけでなく Y も」「X でもない、Y でもない」「X だからではなく Y だからだ」、文末の「〜は不要」「迷わない」のような短い否定などで、Y を直接書く。否定を残してよいのは、範囲や仕様を限定する文（「本番には適用しない」）と、読み手が実際に持っている誤解を根拠を添えて正す文だけ
4. 太字を多用しない。項目名や結論に付いた太字は外し、残すのは 1 つの文章で数か所までにする。強調したいことは文の先頭に置くなど、語順と構造で表す
5. 句読点は「、」と「。」を使う。「，」「．」は直す
6. 短く書く。「〜することができる」→「〜できる」、「〜を行う」→「〜する」、「これにより」「〜という形で」のような中身の無いつなぎは削る。検討の経緯や判断の変遷を書いた部分は結論だけを残す
7. 和文と半角英数字（インラインコードを含む）の間のスペースは、上の設定に従う
   - 「入れない」のとき: 「6ファイル」「`foo`の設定」のように詰める。原文にあるスペースは外す
   - 「入れる」のとき: 「6 ファイル」「`foo` の設定」のように半角スペースを 1 つ入れる。句読点や括弧の隣には入れない
   - どちらの場合も、URL の前後、「a / b」のような区切りのスラッシュの前後、コードブロックの中はそのままにする

## 出力の形

直す箇所が無いときは「直す必要はありません。」とだけ書く。

直す箇所があるときは、次の 2 つだけを順に書く。ほかの説明や感想は書かない。

1. 「## 校正後」の見出しの下に、直した全文を「{{FENCE}}」で始まり「{{FENCE}}」で終わるコードブロックに入れて書く。全文をそのままコピーして使えるようにする
2. 「## 変更点」の見出しの下に、変えた箇所を 1 行に 1 件の箇条書きで「元の表現 → 直した表現（理由）」の形で書く。理由は短く書く
